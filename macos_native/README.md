# SwiftPeek · macOS 26+

原生 SwiftUI / AppKit 客户端。使用 macOS 27 SDK 构建，最低系统版本为 macOS 26（0.8.1 起）。
取流、签名、弹幕协议、关注与历史、FLV 解复用与硬件渲染复用 iOS 实现。

## 下载与安装

当前版本 **0.8.5 (19)**：[下载 Universal ZIP](https://github.com/Rladmsrl/SwiftPeek/releases/download/v0.8.5-macos/SwiftPeek-0.8.5-macOS-universal.zip)，解压后将 SwiftPeek.app 拖入“应用程序”。同一包包含 Apple Silicon arm64 和 Intel x86_64，最低 macOS 26。Intel 与 macOS 26 真机播放尚未验证。

包采用 ad-hoc 签名，未做 Developer ID 公证。核对[发布页](https://github.com/Rladmsrl/SwiftPeek/releases/tag/v0.8.5-macos)的来源与 SHA-256 后，如被系统阻止，可按提示在“系统设置 → 隐私与安全性”允许该应用。包内隐私检查通过不代表完整安全保证，详见[隐私说明](../PRIVACY.md)。

## 打开与构建

运行构建脚本后，App 位于 `build/Build/Products/Release/SwiftPeek.app`，双击打开。
如果正在使用之前的 Debug 版本，请自行退出旧版后打开这个 Release 版本。

```sh
# 仓库根目录；需要 Xcode 27.1 和 xcodegen
./macos_native/build.sh
```

脚本只构建，不启动 App、不操作桌面。工程由 `project.yml` 生成。
本命令生成本机构建产物，采用 ad-hoc 签名。公开发布使用独立的清理、打包与审计流程，见[发布流程](../docs/releases.md)。

## 界面与交互

- **发现**：焦点推荐、16:9 直播卡片、自适应网格、鼠标悬停反馈。
- **分类**：一级分区以玻璃胶囊平铺，二级分类显示图标卡片；支持筛选和返回。没有多级下拉菜单。
- **关注 / 历史**：统一卡片；关注状态支持刷新，右键可以取消关注或删除历史。
- **搜索**：主播 / 直播间搜索；输入房间号、斗鱼网页链接或 `simplelive://room/74751` 可直接打开。
- **直播窗口**：独立会话、主播信息、关注、可收起弹幕面板、画面内悬浮控制条、全屏、画中画。
- **设置**：通用 / 播放 / 弹幕 / 记录与诊断四个分区，修改自动保存。
- 深浅色跟随系统，也可以在设置中切换。悬停与导航动画尊重系统“减少动态效果”。

玻璃效果采用系统 `glassEffect`、`GlassEffectContainer`、`glassEffectID` 和 `.glass` 按钮样式，
用于导航、筛选、搜索和播放控制。内容卡片保留稳定底色，避免长文和封面被玻璃折射干扰。
参考：[Apple — Applying Liquid Glass to custom views](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)。

快捷键：`⌘F` 搜索，`⌘0` 返回主窗口，直播窗口内 `空格` 播放 / 停止、`M` 静音、`⌃⌘F` 全屏。
直播无可恢复的暂停缓冲；再次播放会重新加载直播地址。
关闭直播窗口结束该窗口的会话；浏览主窗口不会打断直播。
启动时只展示主窗口，直播间不参与系统窗口恢复。关闭最后一个窗口也不会主动退出应用。

### 0.3.1 窗口关闭修复

本机两份崩溃报告确认：关闭直播间时，HTTP 接收器的 `DispatchSemaphore` 尚有未归还名额，
释放时触发 `Semaphore object deallocated while in use`，导致整个进程崩溃。
接收器改用可取消的条件变量计数器，取消时唤醒等待者并允许丢弃未消费分块。
另通过场景的 `restorationBehavior(.disabled)` / `defaultLaunchBehavior(.suppressed)` 禁止自动恢复直播间。

`Checks/check-backpressure.sh` 是纯 Foundation 回归检查，不启动 App、不联网：
覆盖 1,000 次带积压取消、正常消费归还名额、取消唤醒所有等待者，均已通过。

### 0.3.3 弹幕文字绘制

弹幕文字改为用 Core Text 分别绘制黑色描边和实心填色，先描边、后填充，避免描边侵占细笔画。
测量包含字形外伸与描边留白，按当前屏幕像素比例生成透明图像，再交给 Core Animation 滚动。
未调整弹幕轨道与视频画布布局。

`Checks/check-danmaku-text.sh` 不启动 App、不联网，在离屏位图中检查 144 组文字、字号、颜色和
像素比例组合，确认添加描边后填色 RGB 不受损、字形没有触及位图裁切边界。该检查已通过；
实际播放时的视觉效果尚未复验。

## 0.3.4 画中画与重连

Mac 画中画使用公开 AppKit `NSPanel` 悬浮窗口，直接承载原视频图层，提供置顶、跨桌面、缩放与返回直播间。
它不是系统 AVKit PiP 面板；iOS 保留系统画中画。旧主窗口不再改写小窗的视频尺寸。

直播与录像共用同一套小窗：拖动画面移动位置，拖动右下角把手按视频比例缩放；
悬停后可用图钉按钮切换置顶，用弹幕按钮切换小窗弹幕。偏好会自动保存。
播放控制栏的“弹幕”可快速开关，旁边的下拉箭头打开弹幕浮层：效果预览、画中画弹幕开关（默认关闭）、
字体（标准 / 圆体 / 衬线）、字号与可见度。调整立即生效并自动保存，直播、录像与小窗共用样式。
“设置 → 播放 → 画中画”保留“小窗始终置顶”偏好。
小窗弹幕沿用播放器弹幕开关、字号、颜色、透明度和屏蔽词；录像暂停时冻结，拖动后清屏。
离线检查 `./macos_native/Checks/check-pip-danmaku.sh <产品目录>` 验证弹幕时间线、实际像素合成和本地 H.264 解码；
`check-floating-video.sh` 验证图层归属与缩放几何，不操作窗口。

重连预算不再因首帧出现就清零：短连接反复 EOF 时，2 次同址重试后会重新取地址并换线路；
持续播放至少 30 秒才重置预算。两项修复均有不联网、不打开窗口的离线回归检查。
整体审查的 5 项问题已在 0.3.5 修复，详情见 [审查报告](../docs/macos-review-2026-10-16.md)。

## 0.3.5 审查修复

- 旧连接与新连接独立解码，按播放世代限制渲染写入，等待异步清空完成后才开始新连接。
- 重连时未知开播状态不再当作下播；下播结果二次确认。
- 恢复播放及重新加载保留手选画质与 CDN；取流失败不改动已生效选项。

## 0.4.0 内存缓冲与后台换流

Mac 默认启用约 4 秒压缩媒体内存缓冲，首次播放因此可能多等数秒，直播延迟相应增加。
每条媒体队列以 8 秒 / 16 MiB / 4,096 个 tag 为背压边界；此外还有 URLSession 分块、解析器和系统渲染队列。
高码率达到内存边界时允许较少缓存起播，避免为了凑足 4 秒而死锁。不会写入视频磁盘缓存。

- 单条连接约 240 秒时后台重新签名、取地址并准备另一条连接。这个阈值来自本机多次约 300 秒 EOF 的观察，
  不是斗鱼官方保证的有效期；换流仅在新连接格式可解析、已收到关键帧和足够媒体后进行。
- 旧流仍能播放时，准备失败保留旧流；不会先停旧流再等新地址，也不会因为准备开始就显示重连遮罩。
- EOF / 401 / 403 / 410 直接启动新地址准备，旧缓冲继续消费。应急接管只要求至少约 0.5 秒媒体，
  避免先耗尽旧缓冲来等待完整 4 秒；正常提前换流仍等待约 4 秒。
- 交接时继续使用原同步时钟和显示图层，将新连接时间戳映射到已入队音视频之后，不清空旧渲染队列。
- 多次准备失败有退避和次数上限；播放缓冲耗尽时才暂停时钟并显示重连。停止或切流会取消两条连接，
  迟到的备用连接也会关闭。
- iOS 0.4.0 也已通过移动端播放会话启用相同的缓冲 / 预热流程，并保留系统画中画和后台音频策略；验证边界见 [iOS 说明](../ios_native/README.md)。

日志新增 `buffer.prepare`、`buffer.prepareFailed`、`buffer.sourceEnded`、`buffer.handoff`、
`room.backgroundStreamCommitted`；heartbeat 带 `bufferSeconds`、`bufferBytes`、`renewing`。
HTTP 事件增加连接标识，区分同一个播放器的新旧连接。缓冲模式的 bytes 是已消费的压缩媒体字节累计值。

验证：Mac / iOS 构建，假接口事务检查，以及 `Checks/check-buffered-playback.sh` 的离线缓冲、HTTP 403、
取消、重试、时间线检查。URLSession 测试由自定义 URLProtocol 在进程内响应，没有访问真实直播。
未进行真实视频解码切换、听感或 GUI 试播，不能据离线检查承诺实际切换完全无感。
直播时间戳在跨 CDN 时未必同源，切换可能跳过或重复少量内容；缓冲不足或长时间断网仍会卡顿。

## 录像回放

直播间顶部“录像”、关注 / 历史卡片右键“查看录像”，或在搜索框粘贴录像链接，打开独立的录像窗口。
左侧播放器带弹幕飞屏、弹幕热度进度条与章节刻度；右侧可在弹幕回放、AI 章节和选集之间切换。
快捷键：空格播放 / 暂停，← / → 10 秒，⇧← / ⇧→ 1 分钟，M 静音，D 弹幕，⌃⌘F 全屏。
离线检查：`./macos_native/Checks/check-replay.sh <产品目录>`。详见 [录像说明](../docs/replay.md)。

## 播放诊断

0.8.0 起默认不记录日志，需要在设置中主动开启。清空观看记录与日志同时清理直播历史、录像进度、诊断日志和本机分享临时文件。

日志目录：`~/Library/Logs/SimpleLive/`。
可从侧边栏的日志按钮、帮助菜单、设置或直播间底部菜单打开。

- `playback.log` + 最多 3 个轮转文件，每份约 2 MiB。
- 每行 JSON，包含时间、进程 ID、运行 ID；房间事件包含房间号，播放器事件包含播放器 ID。
- 记录连接主机、HTTP 状态、网络错误码、播放器状态、重连过程、签名是否刷新。
- 记录斗鱼 `show_status` / `videoLoop` 的原始字段值与字段是否可解析，帮助识别状态误判。
- 每 15 秒记录接收字节数、渲染时钟、分辨率与重同步次数。
- 不写完整流地址、签名、Cookie 或弹幕内容；错误文字中的 URL / 常见鉴权字段自动脱敏。
- 直播间底部菜单“记录当前播放状态”会写入 `user.mark`，方便对齐异常时间。

当前实现对未知开播状态保留恢复机会，并对下播结果二次确认。后台换流的诊断日志有助于区分
连接失效、缓冲耗尽与渲染问题。提交公开 Issue 前，请删除日志中不希望公开的房间号、时间与设备信息。

## 代码分工

- `App/MacDesign.swift`：颜色、卡片表面、玻璃控件、悬停、头像和空态。
- `App/MacCards.swift`：直播、推荐焦点、分类卡片与网格。
- `App/MacLibraryView.swift`：主窗口导航和浏览流程。
- `App/MacRoomView.swift`：窗口级播放会话、重连任务取消、直播界面。
- `App/MacSettingsView.swift`：设置窗口。
- `../ios_native/App/Player`：跨平台播放器与弹幕渲染；UIKit / AppKit 宿主按平台区分。
- `../ios_native/SimpleLiveKit`：共享站点核心库及诊断日志。

关注和历史保存在 `~/Library/Application Support/SimpleLive/`；偏好位于 `com.simplelive.mac` 的 UserDefaults。
