# iPhone Duo 兼容：折叠屏界面与验证

设计目标：让视频保持主角，展开后利用额外空间阅读弹幕或选择录像；折叠、旋转和分屏时保留原来的页面与播放会话。

沿用 SwiftPeek 的系统字体、白 / 灰背景、品牌橙和系统玻璃控件。封面仍使用真实站点图片，不引入新的装饰素材。系统导航负责标签、返回、搜索和工具栏；应用不手绘 Duo 侧边导航。

## 规范依据

- [Apple：Duo 上线适配](https://developer.apple.com/iphone-duo/prepare/)：用 iOS 27.1 SDK 获得完整显示区域和侧边系统栏；避免屏幕尺寸、方向与设备型号假设。
- [Apple：Designing for iPhone Duo](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo)：保持跨姿态的信息层级，适配 reserved regions，工具栏提供标题与图标。
- [Apple：Preparing your app for iPhone Duo](https://developer.apple.com/documentation/technologyoverviews/preparing-your-app-for-iphone-duo)：自定义布局读取当前容器的 division / occlusion，不能只依赖安全区。

构建使用 Xcode 27.1 / iOS 27.1 SDK，最低系统仍为 iOS 26。27.1 的 reserved-region 查询有可用性保护；旧系统使用同一套容器尺寸布局。

## 布局行为

| 状态 | 播放页 | 列表与导航 |
| --- | --- | --- |
| 折叠竖屏 / 窄分屏 | 上方视频，下方主播信息与弹幕或选集；信息可滚动 | 根据实际可用宽度安排卡片，系统决定工具栏位置 |
| 折叠横屏 / 宽而矮的窗口 | 空间足够时视频在左、信息与面板在右；空间不足则上下排列 | 不因旋转离开当前页或自动进入全屏 |
| 展开横屏 | 视频与信息面板并排，面板宽度随容器变化 | 增加卡片列数，保留当前标签、搜索与导航栈 |
| 展开竖屏 | 视频在上、内容在下，限制视频高度，给面板保留空间 | 使用可用宽度排布，不按设备型号判断 |
| 书本式半折叠 | 按系统给出的折痕位置分成左右区域 | 网格使用偶数列，并在竖向折痕处留出间隔 |
| 支架式半折叠 | 视频置于上方区域，信息与内容置于下方区域 | 推荐卡片按整卡避让横向折叠带，标准系统容器适配导航与弹窗 |
| 用户进入全屏 | 保留同一个视频宿主；半折叠时仍不跨越折痕，另一侧保留内容 | 隐藏系统栏；退出回到当前姿态，不强制转回竖屏 |

播放器自定义布局采用 `GeometryReader` 与 `ReservedRegion`。同一视图树保留视频和内容两个子视图，仅更新其区域；播放器对象、直播会话和回放进度不以尺寸或姿态为身份。不使用不同条件分支创建多个视频宿主。

摄像头遮挡与折痕分别处理：折痕划分区域；摄像头只收缩受影响区域中损失空间最少的一条边。背景可以延伸，视频、弹幕与交互控件均留在安全区域内。视频默认等比适应，用户仍可显式选择填充。

全屏是明确的用户状态，不再把 compact 高度当作全屏，也不再维护全进程的方向锁。亮度手势从当前视频页实际所在的窗口读取屏幕，避免使用其他窗口或折叠前的屏幕。

窄播放器保留弹幕与全屏快捷操作，其他操作进入“播放选项”；不会因为空间不足而删除功能。弹幕设置面板可滚动，并允许底部面板展开。网格在辅助功能大字体下减少列数。

## 验证方法

离线几何检查覆盖连续的窗口尺寸、横向与纵向折痕、摄像头遮挡、全屏与非全屏，包括非负尺寸、不越界、不重叠和不跨越预留区域：

```sh
mkdir -p .local/duo
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun swiftc \
  ios_native/App/Support/PlaybackLayout.swift \
  ios_native/Checks/PlaybackLayoutCheck.swift \
  -o .local/duo/playback-layout-check
.local/duo/playback-layout-check
```

`SimpleLiveUITests` 包含旋转、全屏退出、直播 / 录像导航与回放面板检查。`-launchReplayLayout 1` 是仅 Debug 可用的空回放页入口，用于离线布局验证，不提供假媒体，也不证明实际回放连续性。

`-launchReplayHash` 可在 Debug 构建中打开公开录像用于真实播放检查，媒体地址不写入测试源码。

`UITests/DuoHingeControl.m` 的模拟器铰链驱动改编自 [Appium WebDriverAgent 的 hinge 实现](https://github.com/appium/WebDriverAgent/pull/1287)，文件保留其 BSD 许可。它只属于 UI 测试 target，且仅在 simulator 编译路径发出模拟传感器事件，不进入 App 产物。每次折叠都读取传感器角度确认，不能仅凭事件发送成功认定切换完成。

在本次 Duo 27.1 环境中，`XCUIDevice.orientation` 改变了枚举但没有改变实际显示方向；方向矩阵需要通过 Device Hub 的旋转控件驱动，并用显示方向、窗口尺寸与截图交叉核实。测试报告必须区分“旋转方法执行成功”和“界面真正旋转”。

## 真机验收

构建成功、几何检查通过或普通 iPhone / iPad 模拟器测试均不能替代 Duo 真机验收。必须依次验证：

1. 折叠竖屏、折叠横屏、展开横屏、展开竖屏；在推荐、搜索、关注、设置、直播和回放页往返切换。
2. 正在直播或回放时连续展开 / 折叠，检查无黑屏闪烁、无重新取流、回放时间持续、选中章节和选集不变。
3. 书本和支架姿态，确认视频、弹幕、时间轴、返回和全屏退出按钮均避开折痕；同时检查系统侧边栏出现后的位置。
4. Split View 最窄宽度、系统最大辅助字体、深浅模式、弹幕设置面板展开；检查重要操作可达且信息能滚动。
5. 画中画进入 / 恢复、后台音频、来电或音频路由变化、内屏摄像头启用时的避让。

设备导出、测试日志、截图和签名设置只存放在忽略的 `.local/` 中。真实设备结果确认前，不对外宣称已完成 Duo 全姿态认证。

## 本轮验证结果（2026-10-23）

自动化验证环境为 Xcode 27.1、iPhone Duo / iOS 27.1 模拟器（24A94425）。随后测试版已安装到 iOS 27.2 的 iPhone Duo，由维护者自行测试并确认可用；该反馈不等同于逐项量化的真机姿态或帧率报告。

| 检查 | 结果 |
| --- | --- |
| 实际显示方向 | 确认外屏 466×678 / 678×466，内屏 951×669 / 669×951；按窗口与截图确认，不按方向枚举推断 |
| 连续折叠 | 0° → 180° → 90° → 0°；传感器逐步回读，页面与章节选择保留 |
| 六个页面 | 推荐、分类、关注、我的、搜索、设置，在两组尺寸下完成折叠检查 |
| 导航 | 标签切换、进入设置、系统返回、搜索范围切换通过 |
| 直播 | 同一折叠过程仅一次 room.open / player.connect，未因折叠重新连接 |
| 真实录像 | 同一过程播放时间 3 → 6 → 9 → 13 秒；仅一次 replay.open，无恢复事件 |
| Duo 全屏 | 最新布局下进入、退出及恢复面板通过 |
| 推荐滚动与点击 | 半折叠滚动、展开再折叠后卡片位置稳定；完整可见卡片能进入匹配房间 |
| 视觉复核 | 热度/时长拆行、卡片横跨水平折叠带、原样 HTML 实体已修复；两方向抽查未见新的明确裁切或重叠 |
| 构建与离线检查 | iOS Release 无签名构建通过；179669 个几何边界断言与相关实体解码测试通过 |

仍未通过或未验证的范围：普通 iPhone / iOS 27.0（24A434）的自动化全屏退出回归仍失败，尚未区分运行时自动化命中问题与实际 App 交互问题，不能宣称所有 iOS 版本兼容检查均已通过；系统画中画实际显示帧率、相机启用遮挡及音频路由中断仍需专项真机核验。

证据保存在忽略的 `.local/duo/`：`duo-portrait-completion`、`duo-layout-final-focused`、`duo-grid-visible-target` 等截图目录及对应 xcresult。测试的边缘裁切卡片合成点击曾存在命中歧义，最终通过项限定为完整可见卡片，不将失败记录覆盖或冒充成功。
