# iOS 小窗弹幕性能

本次处理的反馈是：直播和录像在系统小窗开启弹幕后低帧率，退到后台更明显。

## 查到的问题

- 合成由主线程 24 Hz Timer 驱动，逐帧构建多层 Core Image 图并同步渲染，会与界面操作争用主线程。
- 直播采样使用“距上一张保留帧至少 1/24 秒”，30 fps 输入因此隔帧取样，实际约为 15 fps；浮点间隔比较也会错误丢帧。
- 直播缩放持有取帧读锁，界面取帧可能等待缩放完成。
- 合成依赖应用 GPU 工作。Apple 明确说明 [iOS 会限制后台应用提交 Metal 工作](https://developer.apple.com/documentation/metal/preparing-your-metal-app-to-run-in-the-background)，因此该路径不适合依赖后台持续合成。
- 合成帧使用宿主时钟 PTS，但录像的 layer timebase 使用媒体时间，且同时设置 DisplayImmediately；AVFoundation 头文件明确不建议混用控制时基与立即显示附件。

以上是已确认的代码行为，尚未通过用户真机日志量化每项对实际卡顿的贡献。

## 改动

`PiPFramePump` 使用独立串行队列按 60 fps 目标采集、合成和提交视频，最多保留一份最新输入。主线程仅采集 UI 所有的数据与视频帧，每个视频 tick 请求一次，最多一个待处理采集请求。迟到的工作不排队追赶，系统渲染器产生背压时跳过本帧。

弹幕的排版、文字栅格化和透明图层绘制由单独的低优先级队列处理，最多一个任务在途，目标随视频达到 60 fps。视频队列只缩放新画面并混合已完成的透明图层；弹幕任务繁忙时复用上一张弹幕层，不等待文字绘制，也不降低视频取帧频率。关闭弹幕、拖动、切源和设置变化会立即失效旧图层；迟到结果不能重新覆盖它。

视频缩放采用 vImage，合成写入 IOSurface 支持的像素缓冲，不依赖 Core Image/Metal。直播完整保留最高 60 fps、4 秒共 240 帧；在 480 像素长边以内，根据实际 IOSurface 占用自适应缩小尺寸，让缓存及池/读者余量仍受 96 MiB 预算约束。相比此前的 480 像素保留帧，部分比例下分辨率会降低，以保留全部视频帧。合成输出长边最多 960 像素，输出池限制为 6 帧。

直播按固定采样时刻推进，24/25/30/50/60 fps 输入不主动降帧；缩放不持有取帧读锁。合成 PTS 与对应播放时基一致；暂停冻结弹幕，关闭小窗拒绝迟到提交，重开时使用新 generation。

这只改变 iOS 小窗合成路径，不改变 macOS 原有的 Core Animation 浮窗弹幕路径。60 fps 是调度目标，系统实际显示帧率还受设备、负载和源视频影响。

## 视频优先修复（2026-10-26）

上次改动只把合成输出提升至 60 fps，主线程视频采集和直播保留帧仍限制为 30 fps，导致合成输出中视频画面重复。此次解除两处 30 fps 上限，并将文字绘制与视频提交分离。

- 离线采样检查覆盖 24/25/30/50/60 fps 完整保留，以及 120 fps 输入限制至 60 fps。
- 真实 H.264 编解码检查保留连续 4 秒的 240 张不同视频缓冲，包括最早的未播放帧；同时验证实际分配大小符合 96 MiB 预算。
- 将弹幕工作队列完全阻塞 1 秒，视频输出 61 张不同画面；恢复密集弹幕后 1 秒输出 60 张不同画面。该检查读取实际输出像素区分源帧，避免把重复帧计为视频流畅度。
- 异步透明图层的实际像素、暂停冻结、隐藏/显示、拖动清空、切源、重置及迟到结果拒绝检查通过；原有背压、停止和旧 generation 检查通过。
- iOS Release 无签名编译通过。这些结果是 Mac 上的离线检查；此次尚未量化真机前后台系统 PiP 的实际呈现帧率。

## iOS 播放复查（2026-10-26）

再次按真实输入与生命周期检查后，补充修复：

- **毫秒时间戳误丢帧**：FLV 的 60 fps 输入以 16/17 ms 间隔表示，原采样容差只有 1 微秒。4 秒截断时间戳用例仅保留 183/240 帧；容差改为覆盖 1 ms 量化误差后，截断和四舍五入时间戳均保留 240/240 帧，24/25/30/50 fps 同样完整保留。
- **换流缓存串用**：直播重启、重连和时钟重同步显式重置小窗解码器；压缩帧携带播放 generation，旧任务迟到提交会被拒绝。小窗按源标识和清屏 token 失效缓存画面；录像替换 item 时停止旧合成源，等待新视频就绪。直播暂停时同步冻结弹幕。
- **录像加载/定位竞争**：加载中暂停会更新自动播放意图；初始定位、连续 seek 和 item 替换使用 generation 验证完成回调。旧 item 的尺寸、结束/失败通知不能影响新 item；新 item 清空旧时长和尺寸；补齐不足一秒的起播定位和未知时长时的负向跳转边界。
- **录像后台音频关闭无主动暂停**：后台非 PiP 时按设置暂停，前台只恢复因后台而暂停的播放；手动暂停取消恢复意图。预留 300 ms 等待自动 PiP，退出 PiP 后重新应用后台策略，后台设置变更即时进入同一流程。

验证：小窗检查、真实本地 H.264/AVPlayer 录像加载与后台控制检查、移动端会话检查、直播缓冲换流检查、generation/异步 flush 检查均通过；iOS Release 无签名构建通过。检查不使用私人播放地址，不安装或发布应用。系统 PiP 的实际前后台显示帧率、自动 PiP 转场和音频路由仍需真机验证。

## Duo 真机追查：B 帧误采样（2026-10-26）

用户反馈安装上述版本后，直播小窗关闭弹幕流畅，打开弹幕后视频仍卡。新增 `pip.live.stats` 分开记录解码输入/输出、采样拒绝、缓存淘汰和缓存相对音频时钟的位置。真机记录显示：

- 合成与弹幕均约 60 fps，视频合成约 0.4 ms，合成背压丢帧为 0。
- 解码输入与输出约 22–29 fps，但每 5 秒被采样器拒绝约 78–105 帧；成功提交的新视频画面仅约 6.6–7.8 fps。
- 同期解码错误、缓存淘汰和取帧 miss 为 0，说明卡顿发生在采样阶段。

根因是采样器假定解码回调的 PTS 单调递增。含 B 帧的 H.264 会先解码参考帧，再返回显示时间更早的 B 帧；原先的单调采样截止时间将正常 B 帧误当成过期帧丢弃。此前真实 H.264 测试显式关闭了帧重排序，没有覆盖这一场景。

修复改为按 PTS 的 60 Hz 时间槽去重，允许回调乱序，随后仍按 PTS 排序缓存。保留毫秒量化容差，并限制采样槽历史大小。新增乱序 I/P/B 时间戳和真实 High Profile H.264 重排序测试，同时断言编码器实际产生了非单调 PTS；修复前后者失败，修复后两种编码模式均完整保留 240/240 帧。签名 Release 编译通过，已将修复版重新安装到 Duo；安装成功不等同于实际小窗帧率验证。

安装后的同一路直播复测（11:21:48–11:22:22 UTC）：用户确认小窗明显流畅；新视频画面提交约 29.6–30.1 fps，合成提交 60 fps，弹幕图层多数区间约 60 fps。所有该窗口的采样拒绝、缓存淘汰、取帧 miss、解码错误及合成背压丢帧均为 0，视频合成约 0.41–0.65 ms。这路流的实际视频更新约 30 fps，结果证明其不再被降至约 7 fps；60 fps 视频的完整保留另由上述编解码回归覆盖。日志统计的是提交的新画面和图层，不等同于系统屏幕呈现计数。

## 验证（2026-10-23）

- iOS Debug 编译通过；直播与真实录像的画面内播放、弹幕开关、设置保存/重开 UI 回归通过。
- 离线检查覆盖真实 H.264 解码、24/25/30/50/60 fps 输入采样、实际合成像素、字幕方向、暂停/恢复、拖动清空、显隐和切源。
- 工作队列在没有新 UI 输入的 0.8 秒中输出 48 帧，且弹幕像素持续移动；背压、停止后的迟到帧、旧 generation 提交拒绝检查通过。
- 同一台 Mac 的离线压力用例（1080p 输入、360 次合成、舍弃前 60 次预热、峰值 69 条可见弹幕）：平均合成耗时由约 5.11 ms 降为 2.43 ms，P95 由约 7.91 ms 降为 3.06 ms。两次均无合成失败。这是合成耗时对比，不是真机 PiP FPS。
- Duo iOS 27.1 模拟器在测试进程和 App 上下文均报告系统 PiP 不受支持。该项明确跳过；没有用模拟浮窗冒充系统小窗。随后测试版已在 iOS 27.2 Duo 上安装，由维护者自测并确认可用；真实前后台 PiP 显示帧率尚未量化采集。

运行离线检查：先构建共享 macOS 库，再执行 `macos_native/Checks/check-pip-danmaku.sh <包含 SimpleLiveKit.o 的产物目录>`。

真机开启系统小窗弹幕后，每 5 秒记录一次本地 `pip.composite.stats`：`enqueuedFPS` 是提交帧率、`sourceFPS` 是成功提交的新源帧变化频率、`danmakuFPS` 是成功提交的新弹幕图层频率、`meanRenderMS` 是视频合成平均耗时（不包含独立弹幕任务）、`maxInputAgeMS` 是输入采样延迟、`dropped` 是背压/缓冲池导致的跳帧数。提交帧率不能直接当作系统实际呈现帧率。日志不包含弹幕正文、设备标识或播放地址，按仓库要求保留在本地。
