# 手机多看（第一版）

## 使用流程

1. 先正常打开一个直播间，在播放器控制条点「加看」。普通和全屏播放器均提供同一个入口；推荐、关注等列表页不提供独立的多看入口。
2. 弹出的选择面板有「历史 / 关注 / 搜索」三个来源。可以多选，也可直接输入房间号或斗鱼链接；主播名称需要提交搜索。当前播放的房间计入四路上限，选择过程中继续播放，取消不会改变现有会话。
3. 点「添加」直接进入多画面，保留当前房间，再逐路启动新增房间；没有介绍页或再次确认起播的步骤。多画面右上角加号继续使用同一个选择面板，最多同时四路。
4. 点画面或主播名切换主画面和声音。橙框标识主画面；每格底栏有独立扬声器按钮，一点关闭该路声音，再点恢复。点其他格的扬声器切换声音来源，不改变主画面；默认仅一路出声。
5. 底栏可放大 / 返回多画面、全部静音、打开弹幕。更多菜单提供等分 / 主次布局、锁定声音及画中画。
6. 每格的更多菜单提供独立暂停 / 重试、画质、线路、交换位置和移除。顶部返回按钮关闭新增房间并回到原播放器，原房间继续按当前播放 / 暂停状态运行；更多菜单的「结束全部播放」也会暂停原房间。

选择面板在搜索激活时仍保留列表内的「添加」，不依赖可能被系统搜索栏收起的导航工具栏。已播放的房间不可重复勾选；新增选择提交前不建立连接。

## 普通手机与 Duo

所有手机都支持 1–4 路，不根据机型锁定数量。实际布局按容器尺寸与系统保留区域计算。

| 场景 | 布局 |
| --- | --- |
| 普通手机 / Duo 外屏竖屏 | 单路上方视频；双路上下排列；三路一主两副；四路 2×2，下方提供主房间弹幕 |
| 普通手机横屏 | 双路左右排列；四路 2×2；弹幕通过底栏打开，优先保留视频空间 |
| Duo 展开 / 平板宽窗口 | 足够宽且高时，视频网格旁提供独立弹幕面板 |
| Duo 书本式半折叠 | 按真实折叠带分左右两区，四路各放两路，整格避开折叠带 |
| Duo 支架式半折叠 | 主画面在上，其他画面在下；点选改变主画面，播放器对象不替换 |
| 放大单路 | 保留主画面的原视频宿主；有折叠带时利用另一侧显示弹幕 |

折叠、旋转、交换位置和等分 / 主次切换只更新布局，不重新创建播放器。放大时会暂停隐藏且不承担声音的房间，返回后以新地址恢复；这是主动节省资源，与单纯旋转不同。

## 性能与生命周期

- **四路上限、错峰起播**：相邻房间的起播间隔为 350 ms，避免同时集中请求签名和建立连接；单路加载失败不会阻塞其他路。
- **自动画质**：原房间保持现有画质以避免进入时重连；新增副画面默认最低档。使用自动画质的房间成为主画面后采用站点提供的中间档，切声音 900 ms 后再调整画质，减少快速切换产生的请求。站点档位数量和码率不同，不承诺固定分辨率。
- **尊重手动选择**：每路可以独立手动选画质；不会覆盖普通单房间的全局画质或音量偏好。手动高画质会增加资源消耗。
- **弹幕与小窗**：只有主画面绘制滚动弹幕；列表展示最近 80 条，消息缓存有 300 条上限。非主画面且未进入画中画的房间丢弃弹幕消息，不批量刷新界面；切回来继续接收。仅声音来源（或主房间）绑定画中画，不对四路进行视频合成。
- **低电量 / 发热**：系统低电量模式或 serious / critical 温度状态使自动画质降至最低，并停止滚动弹幕绘制；压力解除后恢复自动策略。收到内存警告时切到单画面，暂停其他无声房间。
- **后台**：仅保留声音来源的后台音频（按用户设置）及活动画中画。其余流停止；自动画中画候选保留原有 300 ms 启动宽限期。回前台恢复之前正在播放的房间，用户主动暂停的房间保持暂停。
- **音频会话**：直播与录像按播放器持有共享音频会话的使用权；关闭一路只释放自身占用，最后一路退出才停用系统音频会话。
- **与原播放页协调**：原播放器借出同一个播放会话和视频图层，进入 / 返回不重建连接；被遮盖的视频宿主不再修改已借出的图层尺寸。其他隐藏的直播 / 录像暂挂，避免抢占声音。移除原房间或结束全部播放会保留其暂停意图，返回时不擅自重播。

不持久化多看组合或媒体地址。不同房间保持各自直播时钟，不保证不同主播视角同步到同一时刻。

## 检查

离线几何与输入解析：

```sh
mkdir -p .local/multiwatch
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcrun swiftc \
  ios_native/App/Support/MultiWatchLayout.swift \
  ios_native/App/Support/MultiWatchRoomInput.swift \
  ios_native/Checks/MultiWatchLayoutCheck.swift \
  -o .local/multiwatch/layout-check
.local/multiwatch/layout-check
```

会话检查复用 `macos_native/Checks/check-mobile-playback.sh`，须传入与当前源码匹配的 macOS 构建产物目录。覆盖四路独立起播、去重 / 上限、单路声音、声音锁定 / 静音、布局保持对象身份、隐藏 / 后台暂停、用户暂停意图、移除 / 退出释放、迟到请求以及音频占用计数。

`MultiWatchUITests` 覆盖播放器加看、取消不改变页面、历史 / 关注 / 搜索来源、直接添加至四路、返回原播放器，以及四宫格、切声音、静音、放大恢复、移除、横屏和辅助功能字体。也检查列表页不再出现独立入口。`-launchMultiWatchLayout 1...4` 与 `-launchRoomLayout 1` 是仅 Debug 的离线空画面入口，不加载媒体，不代表真实直播验证。

Duo 折叠 UI 检查必须在具备铰链传感器的模拟器或设备上执行，普通手机环境明确跳过；几何通过不能替代折叠系统行为或真机性能验证。

真机验收需在普通 iPhone 与 Duo 上分别进行：四路持续播放、连续折叠 / 旋转、手动高画质、低电量 / 发热、后台 / 画中画切换、蓝牙 / 来电中断。记录实际帧率、内存与热状态，不用模拟器或离线假播放器结果宣称真机四路稳定。
