# SwiftPeek 0.8.6 — 直播稳定性与状态准确度

版本 **0.8.6 (20)**。

## 直播播放稳定性

- 缓冲目标不再是固定 4 秒：首次起播按网络速度给 2 秒起步，卡顿后逐级抬高续播余量（2 → 3 → 4.5 → 6 秒），稳定播放一段时间后再逐级回落，避免「卡—播—卡」的循环。
- 网络断开时不再反复重连失败，改为暂停等待；网络恢复或切换接口（Wi-Fi ↔ 有线 ↔ 热点）后立即重连续播，状态提示改为「网络已断开，恢复后自动续播」。
- 弱网下可自动降一档清晰度（需在设置中开启「弱网自动降低清晰度」）：90 秒内出现 3 次带宽不足导致的卡顿才会触发，且只影响当前窗口，不改默认清晰度设置。
- 卡顿时长与连接超时按网络状况区分：连接阶段（DNS / TLS）给 8 秒，已连上但 4 秒没有数据才判定连接已死，不再让慢请求占满整个超时窗口。
- 后台换流时，替换连接拿到的是「够续播的余量」窗口，而不是在已经冻结的时间上再叠一个完整超时。

## 线路与签名

- 各 CDN 线路仍并行解析，但拿到第一条可用地址后只再等 1.2 秒；响应慢的线路会被取消，不再让首帧和每次恢复都跟着最慢的那条等。
- 指定线路全部失败时自动退回全部线路，让调用方换到可用的一条。
- 签名脚本按房间缓存，超过复用窗口后不再每次重新下载脚本；若斗鱼轮换了脚本导致取流失败，会自动重取脚本并重签一次。

## 直播状态

- 直播间状态从两态（直播 / 轮播）扩展到四态：直播中、轮播、未开播、状态待确认。列表里的 `rst` 只表示房间展示类型，标为轮播的房间主播可能正在直播，因此会按房间确认一次状态再显示。
- 关注的列表按「正在直播 / 轮播中 / 未开播」分组；轮播用循环图标、未开播用静态标记，只有分组标题旁那个点会做脉冲动画（减少动态效果时静止）。
- 搜索结果的直播 / 未开播判定改用 `isLive`，主播搜索结果再结合 `isLoop` / `videoLoop` 区分直播与轮播。
- 封面角标只标「轮播」和「未开播」，直播是默认状态不额外标记。
- 分类翻页修正：推荐接口的 `pgcnt` 恒为 0，改为翻到没有房间为止；分类接口使用真实页数，不再提前判定「没有更多」。

## 界面与性能

- 播放页弹幕层、回放进度条、当前章节各自包成独立的观察边界，弹幕每 80ms 合并一批只重算弹幕层，不再带着控制条、信息行和工具栏一起重算。
- 关注页与分类页在切回应用、或从其它页面返回时按需刷新过期数据，不再只是打开那一刻准确。

## 下载与安装

- `SwiftPeek-0.8.6-macOS-universal.zip` 支持 **macOS 26+**，包含 **Apple Silicon arm64 与 Intel x86_64**。解压后将 `SwiftPeek.app` 拖入「应用程序」。
- 应用使用不包含个人身份的 **ad-hoc 签名**，未经 Developer ID 公证。核对来源和 SHA-256 后，可按系统提示在「系统设置 → 隐私与安全性」允许打开。
- 同时提供匹配本标签的 `SwiftPeek-0.8.6-source.zip` 和 `SHA256SUMS.txt`。

## 验证范围

Universal 双架构构建与包内隐私检查通过，共享库测试与 macOS 播放检查通过。

Intel 架构为交叉编译，尚未完成 Intel 设备或 macOS 26 真机的安装与播放验收。弱网自动降清晰度、断网恢复等行为依赖实际网络环境，建议在真实弱网下自行验证。
